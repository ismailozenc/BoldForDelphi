# Bold for C#

The C# port of Bold for Delphi, on .NET 10. The Delphi source in [`../Source`](../Source) is the specification; this folder holds the port, its tests and the tools that link the two.

To use Bold in an application, start with the [user guide](docs/USER_GUIDE.md): packages, a first application, models, typed classes, persistence, the GUI, multi-user and deployment. Its [tutorials](docs/TUTORIALS.md) build nine runnable examples on one model, from a first system to desks over the network ([`examples/Library`](examples/Library)).

## Build and test

```
dotnet build CSharp/Bold.slnx
dotnet test CSharp/Bold.slnx --logger trx --results-directory CSharp/TestResults
dotnet run --project CSharp/tools/Bold.PortTool -- report
```

`Bold.WinForms` and `Bold.ModelEditor` target `net10.0-windows`; build them on Windows. GitHub Actions builds and tests everything on Windows for every push ([`.github/workflows/csharp.yml`](../.github/workflows/csharp.yml)) and shows the port status on the job page.

## Packages and deployment

```
powershell -ExecutionPolicy Bypass -File CSharp\deploy\install.ps1     # install on this machine (Windows; pwsh CSharp/deploy/install.ps1 elsewhere)
dotnet pack CSharp/Bold.slnx -c Release      # only the NuGet packages and the bold-codegen tool, into CSharp/artifacts/packages
bash CSharp/deploy/check.sh                  # the same, proved: an application on the packages alone, the programs published and started
```

[`deploy/install.ps1`](deploy/install.ps1) needs only the .NET 10 SDK: it packs, makes `CSharp/artifacts/packages` the package source `bold`, installs `bold-codegen` as a global tool and publishes the programs into `CSharp/artifacts/publish`. After it, `dotnet add package Bold.Persistence.Sql` works in any project on the machine; `-Uninstall` undoes it.

Every library is a package (`Bold.ObjectSpace`, `Bold.Persistence.Sql`, `Bold.Handles`, `Bold.WinForms`, ...), with its Delphi type aliases, which the package compiles into the projects that use it; `Bold.SourceGenerators` is an analyzer package and `bold-codegen` a .NET tool. Both servers run from a console, as Windows or systemd services, and in containers ([`deploy/docker`](deploy/docker), [`deploy/systemd`](deploy/systemd)), and answer `/health`. CI keeps each run's packages as the `packages` artifact; the user guide's Deployment section has the details.

## Typed classes

`bold-codegen` writes the classes of a model (`.bld`) as C#:

```
dotnet run --project CSharp/tools/Bold.CodeGen.Tool -- Model.bld --out <folder>
```

For each class it writes `<Class>.g.cs` (a partial class with a property for each member, a typed list class, and the
model's methods as partial methods), for each component `<Component>.g.cs` (which registers the classes with Bold), and
`<Class>.cs` with a stub for each method the model declares; it only ever adds to `<Class>.cs`. A component is a
namespace. A system uses the classes when its type info is built with generated code (`TBoldSystemTypeInfo(model, true, ...)`);
see [`examples/Building/BuildingClasses`](examples/Building/BuildingClasses). A model with custom attribute types needs
their type names: `--typenames <file>` adds them from a file with a line a type, as `TBoldTypeNameDictionary.SaveToFile`
writes them (see [`examples/CustomAttributes/Shapes.typenames`](examples/CustomAttributes/Shapes.typenames)).

## Handles

`Bold.Handles` has Bold's non-visual components: a model component feeds a `TBoldSystemTypeInfoHandle`, a
`TBoldSystemHandle` runs a system on it, and expression, list, cursor, reference, variable, derived, filtered, sorted
and SQL handles hand out elements that stay current as objects change. They are `System.ComponentModel` components:
pass a container to the constructor, and the WinForms designer's `BeginInit`/`EndInit` stand in for Delphi's loading
from a form (a system handle set `Active` while loading starts at `EndInit`).

```csharp
var components = new Container();
var model = new TBoldAbstractModel(components);
model.ReadModel(bldLines);
var typeInfo = new TBoldSystemTypeInfoHandle(components) { BoldModel = model };
var system = new TBoldSystemHandle(components) { SystemTypeInfoHandle = typeInfo, Active = true };
var people = new TBoldListHandle(components) { RootHandle = system, Expression = "Person.allInstances" };
```

## Bold-aware GUI

`Bold.AwareGui` has what Bold's controls are made of, without the controls: followers that keep a value of an
element on show and write edits back, the controllers and renderers of strings, numbers, dates, check boxes, viewers,
lists, trees and grids, the handle followers that connect them to handles, the actions (system, list and undo actions)
and the properties controllers that drive properties of any component. It does not depend on WinForms, so its logic is
tested on every platform; `Bold.WinForms` builds the controls on it. Followers display through the environment's
queue, which the GUI runs when idle (a test can call `TBoldQueueable.DisplayAll()`).

```csharp
var rows = new TBoldStringFollowerController(null) { Expression = "firstName" };
var list = new TBoldListAsFollowerListController(null, rows);
var follower = new TBoldListHandleFollower(listBox, list) { BoldHandle = people };
// after display: follower.Follower.SubFollowers(i) is the row of the i-th person,
// rows.GetCurrentAsString(row) its first name
```

## WinForms

`Bold.WinForms` has the Bold-aware controls (edit, label, check box, combo box, list box, grid, tree view, navigator,
memo, rich edit, image, track bar, progress bar, page control and the data set), the auto forms that show any element, the forms of the
persistence layer and the editors of OCL, type names and grid columns. A control has `BoldHandle` and
`BoldProperties` (its follower controller), as in Delphi. `BoldWinForms.Initialize` runs when the library is first
used and installs the WinForms environment: followers display when the application is idle. `TBoldActionLink` links a
button or a menu item to an action, as Delphi's `Action` property did:

```csharp
var grid = new TBoldGrid { BoldHandle = people, Parent = form };
TBoldActionLink.Link(saveButton, new TBoldUpdateDBAction(components) { BoldSystemHandle = system });
BoldAFP.AutoFormProviderRegistry().FormForElement(person)?.Show();
```

[`examples/Building/BldOwn`](examples/Building/BldOwn) is Delphi Bold's Buildings and Owners example on WinForms and
SQLite; a test runs it.

## Multi-user

Several applications on one database stay in step through Bold's propagator, and can take pessimistic locks through
its lock manager. `Bold.Propagator.Server` is the server: the propagator and lock manager of Delphi's enterprise
propagator, on ASP.NET Core, with a SignalR hub at `/propagator` where Delphi had DCOM. It reads
`Bold.Propagator.Server.ini` next to the program, as Delphi's server read its own INI file:

```
dotnet CSharp/src/Bold.Propagator.Server/bin/Release/net10.0/Bold.Propagator.Server.dll --urls http://0.0.0.0:5050
```

Another ASP.NET Core application can host it too, the remote persistence server for one (`services.AddBoldPropagator()`
and `app.MapBoldPropagator()`).

A client application puts a snooper and an ID adder in its persistence chain, and a listener with an external object
space event handler brings the other clients' changes in. `TBoldSignalRPropagatorHandle` reaches the server's hub; the
client needs no package, it speaks SignalR's protocol over a WebSocket itself:

```csharp
var propagator = new TBoldSignalRPropagatorHandle(components) { Url = "http://server:5050/propagator" };
var snooper = new TBoldSnooperHandle(components) { BoldModel = model, NextPersistenceHandle = database, PropagatorHandle = propagator };
var events = new TBoldExternalObjectSpaceEventHandler(components) { BoldSystemHandle = system, PropagatorHandle = propagator };
var listener = new TBoldListenerHandle(components) { PropagatorHandle = propagator, Dequeuer = events };
system.PersistenceHandle = new TBoldIDAdderHandle(components) { NextPersistenceHandle = snooper, BoldListener = listener };
propagator.Connected = true;
system.Active = true;
```

For pessimistic locking, give the model region definitions and add a `TBoldLockingHandle` with a
`TBoldSignalRLockManagerHandle` (and the same lock manager handle on the snooper). `TBoldInProcessPropagatorHandle`
and `TBoldInProcessLockManagerHandle` reach a server in the same process, as the tests do. Without a server,
`TBoldUDPModificationBroadcaster` tells the other clients of changes by UDP broadcasts on the local network.

## Remote persistence

A client application can reach its database through a server instead of opening it itself, as Delphi Bold's SOAP
persistence did. `Bold.Remote.Server` runs the persistence on ASP.NET Core: requests are posted to `/persistence` and
run on the server's persistence handle, one at a time. Its `appsettings.json` names the model, the database and the
SQL dialect, and with `"Propagator": true` the same host runs the propagator too (its hub at `/propagator`), with a
snooper in front of the database so that every client hears of the changes the others save:

```json
"Bold": {
  "Model": "Model.bld",
  "Provider": "Microsoft.Data.SqlClient",
  "ConnectionString": "Server=.;Database=Bold;Trusted_Connection=True;TrustServerCertificate=True",
  "Engine": "dbeSQLServer",
  "Propagator": true
}
```

On the client, `TBoldHttpClientPersistenceHandle` takes the place of the database handle (the model must be the
server's); put it under an ID adder with a listener, as in the multi-user section, for the client to hear of changes:

```csharp
var server = new TBoldHttpClientPersistenceHandle(components) { BoldModel = model, Url = "http://server:5000/persistence" };
var propagator = new TBoldSignalRPropagatorHandle(components) { Url = "http://server:5000/propagator" };
var events = new TBoldExternalObjectSpaceEventHandler(components) { BoldSystemHandle = system, PropagatorHandle = propagator };
var listener = new TBoldListenerHandle(components) { PropagatorHandle = propagator, Dequeuer = events };
system.PersistenceHandle = new TBoldIDAdderHandle(components) { NextPersistenceHandle = server, BoldListener = listener };
```

Another ASP.NET Core application can offer persistence too, with `app.MapBoldPersistence(handle, model)`.

## XMI

`Bold.Xmi` reads models from XMI files of UML 1.3 and 1.4 (Rose, and the tools that write UML 1.4 with XMI 1.1 or 1.2)
and writes them as XMI 1.0 of UML 1.3, as Delphi Bold's XMI link did. The model is read into a graph of its UML
elements, flattened and boldified as Delphi's model component did it (a root class, names for unnamed ends and
associations, link classes for many-to-many associations), and converted to a Mold model; writing takes the other way,
unboldified and in its packages again:

```csharp
var link = new TBoldUMLXMILink { FileName = "Model.xmi", TranslateRoseTaggedValues = true };
TMoldModel model = link.ImportMoldModel();       // or link.ImportModel(modelComponent)
link.FileName = "Out.xmi";
link.ExportModel(model);
```

`TranslateRoseTaggedValues` reads Rose's `RationalRose$Bold:TableName` as `Bold.TableName`, and writes it back so.
Elements the graph does not keep (state machines, use cases, diagrams) are skipped. An association class is one
element in XMI, so its association takes the class's name.

The same link reads XMI 2 files of UML 2 (Enterprise Architect, MagicDraw, Papyrus and other UML 2 tools), which
Delphi Bold could not, and writes XMI 2.1 with `XMIVersion = TBoldXMIVersion.xmi21`. Tagged values come from Bold's
own extension of each element (`<xmi:Extension extender="Bold">`), from Enterprise Architect's tags, or from applied
stereotypes, each of whose values is a tagged value; library types (`href="...#String"`) are data types of the model.

## Custom attribute types

Delphi Bold made custom attribute types with an IDE wizard; here `Bold.SourceGenerators`, a Roslyn source generator,
writes them when the project builds, from attributes on a partial class (the wizard's questions). Reference it as an
analyzer:

```xml
<ProjectReference Include="Bold.SourceGenerators.csproj" OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
```

```csharp
[BoldValueSet("Color", ValuePrefix = "c")]
[BoldValueSetValue("Red")]
[BoldValueSetValue("Green", "Green", "Grün")]
public partial class TBAColor : TBAValueSet { }          // TColorEnum, AsColor, the values and the registration

[BoldAttributeType("Point", GenerateMapper = true)]
[BoldAttributeField("X", typeof(int))]
[BoldAttributeField("Y", typeof(int))]
public partial class TBAPoint : TBoldAttribute { }       // AsX, AsY, IBoldPointContent, TBFSPoint, TBoldPMPoint

[BoldAttributeType("ShortString")]
public partial class TBAShortString : TBAString { }      // the registration, with the string attribute's storage
```

Each class gets `AddTypeNameMapping(dictionary)`, which adds its type to a type name handle's dictionary, as the wizard
told you to add it to the TypeNameHandle. What the wizard left to "your code here" (a string representation, a
validation) you write in the partial class. The generator reports what keeps a class from being written (BOLDGEN001 to
BOLDGEN010). [`examples/CustomAttributes`](examples/CustomAttributes) has the three kinds, with a model that uses them.

## Object lending (OLLE)

`Bold.Olle` lends objects between Bold databases, as Delphi's OLLE did: a storage gives its own objects (with global
ids) to another, which holds them, changes them and checks them in again, or takes them back unchanged; storages also
synchronize the objects changed since they last did. The state of the lending is kept in each application's database,
in OLLE tables of their own:

```csharp
var olle = new TBoldOLLEHandle(components) { ApplicationPersistenceHandle = databaseHandle };
olle.OLLEController.GenerateDatabase();                  // once: the OLLE tables
olle.OwnObjectHandler.Get(ids, holdIds, "B", valueSpace); // in A: lend, holding what B may change
olle.ForeignObjectHandler.Put(valueSpace, ids, holdIds, "A"); // in B: take them in
```

The model must use global ids, timestamps and read-only flags (Bold's defaults).

## Model editor

`Bold.ModelEditor` is Delphi's UML model editor as a WinForms program: the model's tree, a page for each kind of
element, the plug-ins (OCL validation, the consistency check, the .bld and XMI links) and the editors for tagged
values, constraints, OCL and units. Start it on a model file:

```
Bold.ModelEditor.exe Model.bld
```

## Where things came from

Every ported element carries a `[Delphi(PortStatus.…)]` attribute, and every C# file starts with the Delphi file it ports. In the other direction, every Delphi unit has a comment on its `unit` line naming its C# file, and every `FOLDER_INFO.md` in `Source` lists where its units went. [PORTING.md](PORTING.md) explains the details.
